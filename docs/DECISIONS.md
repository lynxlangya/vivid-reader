# 讨论纪要与决策记录

记录项目早期讨论中做出的决定和理由。新决策追加在末尾；推翻旧决策时，不删除原条目，而是标注"已被 D-xx 取代"。

---

## 2026-10-15 · 初始讨论

### D-01 地图使用真实地理数据，不用 AI 画地图
- **决定**：地名经 LLM 抽取后关联 Wikidata / GeoNames 获取坐标，在真实底图（OpenStreetMap 数据、Natural Earth / Protomaps）上标注。
- **理由**：图像模型画地图会编造海岸线、弄错相对位置；读者无法分辨真假，错误的印象比没有印象更糟。
- **延伸**：《枪炮》特别适合"带时间轴的地图"（农业扩散、南岛语族迁徙），列入后续版本。

### D-02 历史人物优先使用真实画像
- **决定**：皮萨罗、阿塔瓦尔帕等历史人物优先使用 Wikimedia Commons 等来源的历史画像，并标注出处。
- **理由**：AI 画"16 世纪的印加皇帝"大概率是刻板印象。

### D-03 族群样貌不交给 AI 凭空生成
- **决定**：涉及族群（毛利人、莫里奥里人、新几内亚人、科伊桑人等）的外貌，优先真实的人类学照片或博物馆资料；若使用 AI，必须明确标注"AI 示意"。
- **理由**：本书主旨正是反驳种族优劣论，按刻板印象画族群外貌与书的立场相悖。

### D-04 AI 生图只用于"场景示意"
- **决定**：AI 图像用于没有照片可用的场景，如"新几内亚高地村落""新月沃地的原始小麦田""1532 年卡哈马卡广场的对峙"。
- **可视化优先级**：真实地图 > 真实图像资料 > AI 生成示意 > 短视频。

### D-05 防剧透是硬约束
- **决定**：所有读取书本内容的 Agent 工具都强制截断在读者已读位置；模型拿不到之后的原文。
- **理由**：保住阅读乐趣；工具层截断比提示词约束可靠。
- **已知局限**：截断拦不住模型训练时"读过"这本书的记忆。非虚构影响不大；扩展到小说时需额外的提示约束或输出检查。**截断 ≠ 完全防剧透。**

### D-06 释义随语境变化
- **决定**：悬停释义是"**在本书此处**它指什么"，结合上下文生成，而非通用百科定义。

### D-07 逐步生长的知识图谱
- **决定**：读到哪，点亮到哪。已见过的地点、人物随进度累积；同一实体再次出现时提示"第 X 章见过"。

### D-08 对话感知阅读上下文
- **决定**：伴读对话知道读者读到哪、之前问过什么、哪些概念已标记为"已知"。

### D-09 按书籍类型选择可视化，MVP 只做《枪炮》
- **决定**：架构上预留按书籍类型切换可视化方式的空间；MVP 只针对《枪炮、病菌与钢铁》中译本。

### D-10 高亮要稀疏
- **决定**：只标注值得标注的实体；同一章内只标注首次出现；读者标记为"已知"的实体不再标注。
- **理由**：满屏高亮反而更分神，与初衷相反。

### D-11 预处理与按需生成分离
- **决定**：实体抽取、链接等廉价操作在导入时一次跑完；释义按章节预取并缓存；画图等昂贵操作在用户主动触发时生成并缓存。

### D-12 MVP 不做短视频
- **理由**：成本高、速度慢，看视频本身就是一种分神。等前面的功能验证有效后再考虑。

### D-13 Agent 底座使用 Pi（earendil-works/pi）
- **决定**：以库的方式嵌入 `@earendil-works/pi-ai`（多模型统一接口）与 `@earendil-works/pi-agent-core`（Agent 运行时、工具调用）。`pi-durable` 待评估。**不使用** `pi-coding-agent` CLI。
- **理由**：Pi 是 TypeScript 生态、分层清晰；`pi-coding-agent` 默认带 bash / 文件读写工具，且无权限系统，读书 Agent 不需要这些能力。

### D-14 桌面端，选 Electron
- **决定**：macOS 桌面端优先，使用 Electron。
- **理由**：Pi 要求 Node ≥ 22，Electron 自带 Node；Tauri 需额外挂载 Node 进程。书在本地，桌面端在隐私与版权上更稳妥。

### D-15 用户定位：先自用，再开源
- **决定**：先满足自己的阅读需求，之后开源，逐步扩展。MVP 可以"粗糙"，但核心体验要做准。

### D-16 中文译本优先
- **决定**：面向中文译本。实体抽取时由 LLM 同时推测原文名（英文 / 西班牙文等），用中文名 + 原文名联合检索 Wikidata，多候选时由 LLM 结合上下文消歧，并提供手动纠错。
- **理由**：中文译名不统一，是关联真实数据最大的技术风险。

### D-17 啊哈时刻 = 悬停即见
- **决定**：核心体验是悬停后看到地图和 / 或语境释义。
- **决定**：总结**按需**触发（选中段落 / 本章 / 至今），不做每章固定总结。

### D-18 悬停卡片分两层生成
- **决定**：
  - 地图位置、基础事实：预处理阶段算好，悬停立即显示。
  - 语境释义：打开某章时后台预取本章实体的释义（只用截止到当前位置的文本），缓存。
- **理由**：悬停要"秒出"，又不能违背"只用已读内容"。

### D-19 只支持 EPUB
- **决定**：MVP 只支持 EPUB，不做 TXT 及其他格式。（取代早先"EPUB + TXT"的设想。）
- **理由**：EPUB 的目录、章节结构现成可用；阅读位置可直接用 CFI 表示，foliate-js 自带 CFI 解析与比较。
- **注意**：位置处理保留一层很薄的接口，方便以后接入其他格式，但现在不为它多写代码。

### D-20 模型：云端，DeepSeek + GPT Image
- **决定**：只用云端模型。文字（抽取、释义、对话）用 DeepSeek；画图用 OpenAI GPT Image。其他提供商通过 Pi 自行扩展。
- **依据**：`pi-ai` 内置 DeepSeek（`DEEPSEEK_API_KEY`），并提供统一的 `generateImages()` 接口。
- **提示**：DeepSeek 有自动前缀缓存，预处理时把固定指令放在前面、章节文本放在后面以命中缓存。

### D-21 前端使用 React

### D-22 仓库永不包含书籍内容
- **决定**：仓库不放书籍原文，也不放预处理生成的缓存（实体表、释义、图片等）。`.gitignore` 默认屏蔽 `*.epub`、数据库与缓存目录。
- **待议**：衍生数据（如"本书实体表"）能否分享、以何种形式分享。

### D-23 项目名：历历 · Vivid
- **决定**：中文名「历历」，英文名「Vivid」。
- **出处**：
  - "历历在目"——读过的地方和人物，清清楚楚地出现在眼前。
  - 崔颢《黄鹤楼》"晴川历历汉阳树"。
  - "历"字连着"历史"与"游历"。
- **落选候选**（供参考）：卧游 · Wanderleaf、立象 · Imago、青灯 · Lantern、行间 · Interline、渡 · Ferry、经纬 · Meridian、书童 · Page、惊鸿 · Glimpse。
- **可用 slogan**：老子"不出户，知天下"；陶渊明"泛览周王传，流观山海图"。

### D-24 视觉设计交由 OpenDesign 出初版
- **决定**：`DESIGN.md` 采用 [OpenDesign](https://github.com/nexu-io/open-design) 的设计系统格式（视觉主题、色彩、字体、组件、动效、可访问性、禁忌等），由 OpenDesign 生成首版界面原型。产品与技术设计放在 `docs/` 下。

## 2026-10-15 · 视觉设计 v2 讨论

背景：OpenDesign 首版原型（`prototype/vivid-reader-prototype-v1.html`）执行了 `DESIGN.md` 的全部禁忌，但缺少可辨识的视觉特征，看起来像通用的米色 SaaS。v2 方向为“版心与舆图”，完整草案见 `prototype/v2-folio-atlas/DESIGN.md`。以下四条与原规范冲突，经讨论确定。

### D-25 实体标注改为“专名线”
- **决定**：正文实体标注由“1.5px 类型色点状下划线”改为“1px 实线下划线”，线色为类型色按 55% 预混合到宣纸的淡色；悬停时变为 1.5px 类型全色。稀疏规则（D-10）不变。
- **理由**：首版原型中，彩色点状下划线在阅读距离上与 macOS 拼写错误提示几乎无法区分，读者会下意识地以为文字有误。实线淡色线来自旧式标点本中人名、地名下的专名号，既安静，又有中文排印的来源。

### D-26 引入“朱”色，仅用于已读边界
- **决定**：新增朱色（日间 `#A8432F`，夜间 `#D9826A`；对宣纸 5.4:1，对夜间底 6.15:1），**只用于“已读边界”这一个概念**：进度线上的边界刻度、目录中的“以下未读”分隔、伴读栏顶部的边界标识。不得用于按钮、链接、标注或其他状态，可见面积 ≤ 0.5%。石青仍是唯一的界面强调色。朱色出现时必须配有文字说明，不能只靠颜色。
- **理由**：已读边界是读者信任“不会被剧透”的关键标识，首版只是一行烟色小字，几乎看不见。给它一个专属且稀有的颜色，读者会记住“朱线之后伴读看不见”。

### D-27 伴读的话用楷体（三声字体）
- **决定**：字体按“谁在说话”分工：书的原文用宋体；伴读的回答与卡片中“在本书此处”的释义用楷体（霞鹜文楷优先，偏印刷楷，不用书法体）；界面、元信息和读者自己的提问用系统黑体。读者把正文切换为楷体时，伴读回答与释义改用宋体，以保持两种声音的区分。
- **理由**：读者不看标签就能分清一段字是书里写的，还是 AI 说的，这本身也是对“AI 是配角”的视觉表达。

### D-28 标注悬停不加底色
- **决定**：标注悬停时只加粗、加深下划线，文字底不出现任何背景色。
- **理由**：与“禁止背景色块标注”保持一致；关闭 AGENTS.md 待确认项“标注悬停底色”。

## 2026-10-16 · MVP 实施方案

背景：MVP 实施计划见 `docs/IMPLEMENTATION.md`，执行用的 prompt 见 `docs/codex-goals.md`。以下八条经讨论确定，其中 D-31～D-34 关闭了 AGENTS.md 的若干待确认项。

### D-29 数据库使用 Node 内置 `node:sqlite`
- **决定**：主进程使用 `node:sqlite` 的 `DatabaseSync`，不用 better-sqlite3。只在 `src/main/db/` 内部使用，对外暴露 repository 接口；迁移使用编号 SQL 文件。
- **理由**：Electron 44 内置的 Node 24.21 自带该模块，无需为原生模块重编译；单元测试（本机 Node 22）与应用运行的是同一套代码。
- **风险**：Node 仍把它标为 Experimental（API 已稳定）。封装层保证日后可以换回 better-sqlite3。

### D-30 旁注卡舆图用 SVG 绘制，MapLibre 只用于可选大图
- **决定**：卡片内地图用 d3-geo 投影 Natural Earth（world-atlas）数据，绘制成 SVG，包含经纬网、图框刻度、比例尺、定位小地球、参照地和距离线。单击打开的可缩放大图使用 MapLibre GL + PMTiles，放到 M4，属于可选项。
- **理由**：v2 图版语法用 MapLibre 难以实现；悬停 250ms 内就要出卡，为每张卡初始化 WebGL 太慢；SVG 数据随应用打包，可以离线使用。D-01（只用真实地理数据）不变。

### D-31 章节在主进程解析，以逐字往返测试为准
- **决定**：主进程用 fflate + linkedom 解析 EPUB 章节，生成“纯文本偏移 ↔ CFI”映射。验收方式：随机抽 200 个偏移，主进程生成的 CFI 在阅读器中解析回的文字必须逐字一致，不一致率为 0。达不到时，改用一个隐藏的受限窗口解析（sandbox、不加载远程内容、不持有密钥、不调用模型），并把失败证据写入 `docs/spikes/M0-offset-cfi.md`。
- **理由**：让书本内容访问留在主进程，符合 AGENTS.md 的进程隔离规则。关闭待确认项“章节解析的进程边界”。

### D-32 预处理可以读全书，所有出口按已读边界过滤
- **决定**：导入时的流水线可以读全书，但受三条约束：
  1. 抽取阶段模型写下的自由文本（`note` 等）只用于消歧，永不显示，也不进入伴读上下文；
  2. 所有读取路径（给渲染进程的 IPC、Agent 工具、释义输入、足迹、目录统计）都经过 `src/main/content/`，按已读边界截断；
  3. 导入进度只显示数量。
- **理由**：抽取与链接需要全书；剧透防线设在出口，而不是入口。关闭待确认项“全书预处理的权限边界”。

### D-33 已读边界的推进与手动调整
- **决定**：
  - 自动推进只在“站在边界上向后翻页，并在新的一页停留满 5 秒”时发生（阈值写成配置常量，之后再调）；
  - 目录、搜索、引用链接、拖动等跳转永不推进；跳到边界之后时，页边提示“此处在已读范围之后 · 设为已读至此”，读者点击后才推进；
  - 自动推进只增不减；设置中的手动调整可前可后。手动往回调时，这本书的伴读对话归档，另起一段新会话。
- **理由**：ARCHITECTURE 3.2 的“只增不减”指自动推进；手动调整是读者的明确意图。关闭待确认项中“只增不减与手动调整的关系”和“跳读停留阈值”。

### D-34 语境释义只用提及之前的文字
- **决定**：释义的输入只包含该提及之前的本章文字，以及该提及之前同一实体的历次提及短句。缓存键 `(实体, 章节)` 不随边界变化而失效。提及位于边界之后时，卡片不显示释义，只显示基础层。足迹只统计边界之前的提及。
- **理由**：输入只由提及位置决定，与边界无关，缓存可以安全复用。关闭待确认项“释义缓存与边界调整”。

### D-35 MVP 人物卡不显示画像
- **决定**：MVP 人物卡只显示基础事实和生卒时间轴（标出已读部分提到的年份），不显示画像位。真实画像随 v0.2 接入 Wikimedia Commons（D-02 不变）。v2 原型中人物卡的画像占位属于 v0.2。
- **理由**：与 ROADMAP 一致；避免空画框把卡片撑高。“MVP 功能归属”待确认项中的画像部分由此关闭，知识图谱的归属仍待确认。

### D-36 MVP 不用 pi-durable，字体随应用打包
- **决定**：伴读对话直接存在 SQLite 的 `conversations` 表，不引入 `@earendil-works/pi-durable`。楷体（霞鹜文楷 Regular，`lxgw-wenkai-webfont` 1.7.0，OFL-1.1）随应用打包，不在运行时从 CDN 加载；宋体使用系统字体。
- **理由**：每本书一条会话，SQLite 足够，少一个依赖；应用要能离线使用，渲染进程也不发外网请求（CSP）。
